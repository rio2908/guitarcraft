# GuitarCraft для Android

Android-приложение показывает тот же экран, что и веб-версия в `../dist`. При сборке Gradle автоматически копирует HTML, CSS, JavaScript и записи гитарных звуков в APK. Для игры интернет не нужен; при подключении могут дополнительно загрузиться веб-шрифты.

В отличие от Python-игры EnglishCraft, GuitarCraft собирается как небольшое Android-приложение с WebView. Поэтому здесь используются Gradle и AndroidX WebKit, а не Buildozer. Сохранены подходящие принципы: ручная сборка debug APK, постоянный идентификатор пакета, обычная и адаптивная иконки, кэш debug-ключа для обновлений поверх установленной версии, минимальный Android API 24 и архив APK из GitHub Actions. Экран остаётся вертикальным для Redmi Note 7.

## Сборка

Нужны JDK 17 и Android SDK с платформой 35. Откройте каталог `android` в Android Studio или выполните из него:

```powershell
.\gradlew.bat :app:assembleDebug
```

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

В GitHub Actions запустите **Build Android Debug APK → Run workflow**. Артефакт называется **GuitarCraft-Android-debug**. Workflow запускается вручную. В этом локальном checkout нет настроенного GitHub remote; для запуска Actions проект нужно разместить в репозитории GitHub.

## Проверка на телефоне

Установите APK поверх предыдущего APK с тем же package ID `org.game.guitarcraft` и тем же ключом подписи. Проверьте выбор песни, все кнопки прослушивания, сохранение шагов после перезапуска, а также «Проверить звук»: Android должен запросить доступ к микрофону, после чего приложение должно распознать одну сыгранную ноту. При отказе в доступе веб-экран показывает ошибку.

Звуковые файлы и мелодии находятся в APK. Прогресс пока хранится в WebView localStorage. Debug-ключ в Actions сохраняется в кэше; если кэш потеряется, новый APK может не установиться поверх старого. Перед удалением приложения учтите, что экспорт прогресса пока не реализован.

Сборка APK и проверка микрофона на физическом устройстве выполняются отдельно от проверки веб-версии.
